# 26: Explicit manual `run` semantics, parameterization, and terminal-state preservation

**Source:** findings/06 · .scratch/weread-cron-v1/findings/06-manual-run-semantics.md
**Category:** enhancement
**Blocked by:** None
**Related:** ADR-0002 (scheduler & terminal state), ADR-0008 (task lock), ticket 08 (run terminal rules), ticket 24 (unified finalization)
**Status:** resolved

## Agent Brief

**Category:** enhancement
**Summary:** Make `weread-cron run` an explicit, parameterized user-requested Task that runs on demand, accepts required `--minutes` and optional `--book`, bypasses the daily success terminal-state gate, and preserves existing daily `success` terminal state on manual failure.

**Current behavior:**
1. `weread-cron run` accepts no arguments. Any extra argument causes a CLI usage error (`run 不接受额外参数`).
2. `weread-cron run` checks the daily Terminal State gate before starting. If today already has a `success` Terminal State, it is rejected with a message on stdout and the rejection exit status (`ExitRunRejected`).
3. `weread-cron run` calculates its Target Duration randomly from the configured `[ReadMinutesMin, ReadMinutesMax]` range, identical to an automatic daemon Task.
4. `weread-cron run` selects books solely based on configured candidate books or automatic Shelf selection; callers cannot specify a book.
5. If a Task fails, the finalization logic writes a `failed` Terminal State directly, overwriting any previous state for the day.

**Desired behavior:**
1. **Explicit CLI interface**:
   - Usage: `weread-cron run --minutes <N> [--book <bookId>]`
   - `--minutes` is mandatory and must be a positive integer (`N > 0`). Missing, non-integer, or non-positive values result in a CLI usage error with the existing usage error exit status.
   - `--book` is optional. When provided, it specifies the target book ID for the manual Task, bypassing candidate book selection and automatic Shelf selection. When omitted, book selection retains existing behavior (configured candidate books, or automatic Shelf selection if no candidates are configured).
   - `--minutes` sets the exact Target Duration for this Task, overriding the configured random `[ReadMinutesMin, ReadMinutesMax]` range.
   - `--help` / `-h` displays updated usage instructions for `run`.
2. **Independent on-demand execution**:
   - An explicit manual `run` starts immediately and is not constrained by the daemon Run Window.
   - An explicit manual `run` is not blocked by existing daily Terminal State (whether `success`, `failed`, or none).
   - Concurrency protection is strictly preserved: if another Task currently holds the deployment task lock (cross-process file lock or in-process guard), the manual Task is rejected with the existing task-running rejection exit status and message.
3. **Daily Terminal State preservation (anti-downgrade rule)**:
   - Manual execution participates in the daily Terminal State persistence:
     - On manual Task success: records or preserves daily `success` for the Task start date.
     - On manual Task failure: records `failed` only if today does not already have a `success` state. If today already has `success`, the persisted Terminal State remains `success`.
   - Notifications and caller reporting remain faithful to the manual Task result:
     - Configured notification channels (e.g. Bark, WeCom) send the corresponding success or failure notification for the manual Task.
     - The manual CLI process outputs summary and exits successfully on manual success, or reports failure and exits with the standard Task runtime failure exit status on manual failure.
4. **Daemon scheduling independence**:
   - Daemon automatic scheduling continues to evaluate daily Terminal State. A successful manual Task results in daily `success`, which prevents subsequent automatic runs on that day per existing daemon scheduling rules.
5. **Documentation & ADR alignment**:
   - Follow repository ADR maintenance convention: do not rewrite accepted ADR-0002 in-place. Record a new ADR (e.g. `docs/adr/0009-explicit-manual-task-semantics.md`) that clarifies and supersedes the manual run decision of ADR-0002.
   - Update `CONTEXT.md` (glossary terms `Task` and `Terminal State`) and `spec.md` (CLI behavior and user stories) to reflect explicit manual Task semantics.

**Key interfaces and behavioral contracts:**
- CLI argument parsing: validate `--minutes <N>` and optional `--book <bookId>` for `run`. Reject missing or invalid `--minutes` with usage error exit status.
- Invocation boundary: allow callers to pass manual parameters (duration, optional book) and execute the Task without being blocked by existing daily `success` Terminal State, while preserving deployment task lock mutual exclusion.
- Task finalization / Terminal State storage: ensure terminal persistence logic implements the anti-downgrade invariant (never overwrite existing today's `success` with `failed`).
- ADR and documentation updates per repository guidelines.

**Acceptance criteria:**
- [x] `weread-cron run` without `--minutes` exits with CLI usage error exit status and prints usage to stderr.
- [x] `weread-cron run --minutes 0` or `--minutes -5` or `--minutes abc` exits with CLI usage error exit status.
- [x] `weread-cron run --minutes 20` executes a manual Task with exactly 20 minutes Target Duration.
- [x] `weread-cron run --minutes 20 --book 12345` executes a manual Task using book ID `12345`.
- [x] `weread-cron run --minutes 20` without `--book` falls back to existing book selection logic (configured candidate books or Shelf selection).
- [x] When today already has a persisted `success` Terminal State, `weread-cron run --minutes 15` starts and executes instead of being rejected.
- [x] When another Task is currently holding the task lock, `weread-cron run --minutes 15` is rejected with the existing running-task rejection exit status and message.
- [x] If today already has `success`, and a manual Task subsequently fails, the persisted daily Terminal State remains `success` (no downgrade).
- [x] If today has no terminal state or has `failed`, and a manual Task fails, the persisted daily Terminal State is recorded as `failed`.
- [x] If a manual Task succeeds, daily Terminal State is recorded as `success`.
- [x] Manual Task success and failure send corresponding success/failure notifications to configured notification channels.
- [x] Manual Task failure exits with the standard Task runtime failure exit status.
- [x] A new ADR (e.g. `docs/adr/0009-explicit-manual-task-semantics.md`) is recorded superseding the manual run section of ADR-0002, and `CONTEXT.md` / `spec.md` are updated.
- [x] Existing automated daemon tests and regression suites continue to pass (`go test ./...`).

**Out of scope:**
- Automatic daemon Run Window scheduling logic and frequency.
- Reader Context, Reading Session, report protocol, or protocol-validation behavior.
- Automatic book selection probe and fallback algorithms.
- Cross-process file lock implementation or deployment scope.

## Answer

1. **Implementation**:
   - **CLI interface**: Updated `internal/cli/cli.go` to parse `run --minutes <N> [--book <bookId>]`. Normalizes arguments (`--minutes=N` / `--minutes N`, `--book=id` / `--book id`), validates positive integer `--minutes` (exiting with `ExitUsage` = 2 on missing, non-positive, or non-integer values), and captures optional `--book` ID. Updated usage text to document both command synopsis and option descriptions.
   - **Application boundary**: Added `app.ManualRunOptions` and `App.RunManualTask(ctx, opts)` in `internal/app/app.go`. `RunManualTask` bypasses `checkTerminalGate()` to allow immediate on-demand execution, while preserving in-process mutex and cross-process `flock` task locking (`ErrTaskRunning`).
   - **Task execution & Anti-downgrade persistence**: Updated `internal/task/task.go` to accept `task.ManualOptions`. Explicit `Manual.Minutes` overrides config random range, and explicit `Manual.BookID` overrides candidate config and auto-selection. In `Runner.finalize()`, implemented the anti-downgrade invariant: when persisting `failed` result, if today already has `success` terminal state on disk, overwriting is skipped to preserve `success`. Success/failure notifications are still dispatched faithfully to configured channels, and manual runtime failures exit with `ExitConfig` (1).
   - **Documentation & ADR**: Recorded `docs/adr/0009-explicit-manual-task-semantics.md` superseding the manual run gate decision in ADR-0002. Updated `CONTEXT.md` (terms `Task`, `Terminal State`, `Target Duration`) and `spec.md` (user stories 40–42, implementation decisions 1 & 12).
2. **Testing**:

   - Added application boundary tests in `internal/app/app_test.go` verifying exact duration override, explicit book selection, book selection fallback, terminal gate bypass, task lock rejection, and anti-downgrade preservation on failure.
