## Agent Brief

**Category:** bug
**Summary:** 异常间隔重建 Reading Session 时，重新 enter 成功会无条件清零连续失败预算；持续慢故障下 Task 可反复重置预算、永不收敛为 failed 终态。

**Current behavior:**
- 在 timed report 循环中，当距上次被成功接受上报的墙钟间隔超过内部异常阈值（`DefaultAnomalyThreshold`，默认 90s）时，Task 以新的 enter report 重建 Reading Session；该 enter 被接受后，`consecutiveFailures` 被无条件清零。
- enter 成功只能证明 Reader Context / Reading Session 重新建立成功，不能证明后续 timed report 已经恢复正常（timed report 路径可能仍然持续失败）。
- 确定性复现（fake clock + 慢失败 fake server）：每笔 timed report 约 20 秒后失败；Context 刷新与重新 enter 消耗墙钟时间；下一次尝试落在异常阈值之外，异常分支重新 enter 并清零预算，预算永远无法耗尽。观察结果：8 次 timed report 失败、4 次重新 enter、从未形成最终失败；Task 只能通过主动取消结束。
- 影响：持续故障时 Task 可通过重新 enter 反复重置失败预算，失去"有界失败后必须收敛"的保证；长期运行的 Task 持续占用 deployment task lock，阻止 manual `run`、`books` 与后续自动 Task。

**Desired behavior:**
- 无论异常间隔重建如何穿插，Task 都必须在有界次数的 timed report 失败内收敛为 failed 终态 + 失败通知（spec 决策 #7/#9/#12 的有界收敛保证）。
- 连续失败预算只在"timed report 路径已恢复的确凿证据"——一笔被接受的 timed report——出现时清零；仅重建 enter 成功不得清零预算。
- 需要重新定义预算在重建边界上的行为，并同时验证两种场景：
  - 慢失败场景（本 finding 的复现）：收敛为 failed 终态；
  - 真实长间隔场景（主机 suspend，无底层失败）：重建 Reading Session 后 Task 继续并成功（现有 `TestRunAbnormalIntervalRebuildsSession` 为回归锚点，该测试无前置失败，两种语义下都须通过）。
- 内部默认值（节奏、异常阈值、预算数值）不暴露为配置（spec 决策 #13 / ADR-0005），本票不改动这些数值。

**Key interfaces:**
- Task orchestrator 的 timed report 循环：异常间隔重建分支与预算耗尽分支的失败预算记账逻辑（`consecutiveFailures` 的递增/清零条件）。
- 预算清零条件：与"被接受的 timed report"绑定，而非与"重建 enter 被接受"绑定；或等价地保证有界收敛（实施代理自行选择实现方式，验收以行为为准）。
