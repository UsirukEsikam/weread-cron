# 17: daemon 睡眠后启动 Task 前复查仍在 Run Window 内

**Finding:** F7 · .scratch/weread-cron-v1/findings/01-implementation-review.md
**Category:** bug
**Blocked by:** None
**Status:** ready-for-agent

**What to build:** daemon 在启动 Task 前复查当前时间仍处于 Run Window 内；挂起导致越过窗口结束时不启动，改排次日。

## Current behavior

daemon 计算窗口内随机启动时刻后睡眠等待；醒来后只复查当天终态，不复查当前时间是否仍在窗口内。主机在睡眠期间挂起、恢复时已过窗口结束，之前排定的 Task 仍会启动——启动时刻越出 Run Window。

## Desired behavior

daemon 在启动 Task 前复查当前时间仍处于 Run Window 内（或按"窗口约束开始时间"的等价判定）；已过窗口结束则不启动，改排次日。睡眠期间由 `run` 手动执行形成终态的跳过逻辑（现有行为）保持。

## Key interfaces

- daemon 调度循环：睡眠返回后、执行 Task 前增加窗口复查（对"启动时刻在窗口内"的判定；start==end 固定时刻语义需兼容）。
- 与现有终态复查并行；纯决策判定建议放在调度决策层（与 nextStart 同级）以便测试。

## Acceptance criteria

- [ ] 模拟挂起（时间跳变越过窗口结束）后 daemon 不启动 Task，改排次日
- [ ] 窗口内正常启动（回归）
- [ ] start==end 固定时刻语义保持
- [ ] 睡眠期间形成终态 → 跳过自动执行的现有逻辑保持
- [ ] 新增/更新调度测试覆盖挂起场景

## Out of scope

- 窗口语义本身的修改（ADR-0001 保持）
- 补跑历史欠账
