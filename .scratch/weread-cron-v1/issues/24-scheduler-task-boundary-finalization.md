# 24: Task 终结语义收敛——移除 whole-Task 重排与窗口截止机制，统一 finalization 与 Task 日期

**Finding:** findings/04 · .scratch/weread-cron-v1/findings/04-scheduler-and-task-finalization.md
**Category:** bug
**Blocked by:** None
**Related:** 吸收 #15（failed 终态持久化为通知严格前置，不再独立实施）；保留 ticket 12 的 timed-report 有限传输容错（预算内跳过）；#17/#18 保持各自独立 ticket
**Status:** ready-for-agent

**What to build:** 按 findings/04 澄清的产品模型收敛调度层与 Task 终结的边界：

- Task 一旦启动，调度层不再做 whole-Task 自动重排；
- 移除 `FinalFailureAfter` / 窗口截止收敛机制；
- 自动与手动 `run` 使用同一 finalization 语义；
- Task 日期固定为开始日（success 与全部 failed 路径）；
- Terminal State 成功落盘后才发送最终通知（吸收 #15）；
- 异常启动/重启已在窗口内 → 立即执行（不再 `[now, 结束]` 随机）。

## Current behavior

（来自 findings/04 代码验证；ticket 12 遗留的窗口截止收敛机制 + ticket 07/08 既有语义混排）

- daemon 为每次自动执行注入收敛截止时刻 `finalFailureAfter` = 当天窗口结束 − `replanMinGap`；Task 的暂时性失败在截止时刻之前**不写终态**原样返回，daemon 在窗口内重排整个新的 Task。
- 手动 `run` 传零值截止时刻 → 暂时性失败完全不收敛（与自动 Task 的终结行为不同）。
- 不同失败出口终结行为不一致：恢复链耗尽 / 登录失效 / 自动选书失败立即写 failed 终态；`finalizeTransient` 仅在窗口末收敛；timed report 预算耗尽走 `finalizeTransient`。
- 部分终态与通知日期用完成时刻（success、恢复链耗尽、登录失效、自动选书失败），仅收敛路径用 Task 开始日。
- 异常启动/重启在窗口内且无终态时，按 `[now, 窗口结束]` 随机安排，而非立即执行。
- 失败出口在 Terminal State 持久化失败时仅记日志并继续发通知（F5/#15 现状，未实施）。

## Desired behavior

（findings/04 澄清模型 + 维护者指示 2026-09-06；全自动与手动 `run` 皆适用）

1. **正常每日调度不变**：常驻 daemon 每天在完整 Run Window 内随机一个开始时刻。
2. **异常启动/重启**（当天无终态）：窗口未开始 → 正常随机；now 已在窗口内 → **立即执行**（仅限异常恢复场景，不改变常驻 daemon 的每日随机）；窗口已过 → 当天不自动执行。
3. **无 whole-Task 自动重排**：Task 一旦启动，调度层不再于窗口内启动另一个完整 Task。实际开始执行的 Task 以对应终态结束；Task 开始前的 gate / 拒绝（如 `ErrTaskRunning`、已有终态拦截）与进程异常终止不受此约束。
4. **Task 内有界恢复保留**：report 拒绝恢复链、异常间隔重建 Reading Session、timed report 单次传输失败跳过（预算内）不变；恢复耗尽 → 最终结果。
5. **统一 finalization**：Task 的 success / failed 最终结果都先持久化对应的 Terminal State；持久化成功后，再发送对应的最终通知（success / failure）。一切最终结果路径（success 与各失败出口，含 timed report 预算耗尽，以及 renewal / Reader Context / enter / timed 各阶段暂时性失败的最终收敛）都经此同一流程。
6. **稳定 Task 日期**：Task 开始日（TZ）在启动时确定，success 与所有 failed 路径的终态与通知都使用该日期；Task 越过午夜不转移日期归属。
7. **通知严格后置**（吸收 #15）：Terminal State 持久化失败 → 不发最终通知、Task 返回持久化错误；不存在"已发通知但持久化无对应终态"的可达状态。
8. **崩溃恢复规则不变**：进程崩溃 / SIGKILL 未留终态 → 下次启动按异常启动规则（窗口内立即开始全新 Task，无 checkpoint / resume）。
9. **failed 终态可手动重试**：`weread-cron run` 在 failed 终态下可重试并更新为 success（既有规则不变）。
10. **timed-report 传输容错保留**：连续传输失败预算（3 次）内跳过节奏点、会话继续；预算耗尽 = Task 级最终失败（不再是"调度层窗口内重排"的触发）。

## Key interfaces

- `TaskRunner.RunTask`：移除 `finalFailureAfter time.Time` 参数（interface、App 实现、CLI seam、daemon 调用点同步）。约束限定为**实际开始执行的 Task**：正常完成或最终失败都必须形成对应 Terminal State（success → success 终态；最终失败 → failed 终态）。Task 开始前的 gate / 拒绝（`ErrTaskRunning`、已有终态拦截）与进程异常终止（无终态，下次启动按异常启动规则）不属于该约束；终态持久化失败等存储级错误返回错误且无终态。
- `Options.FinalFailureAfter`：删除；暂时性失败的统一出口变为无条件最终收敛（不再检查截止时刻），与既有失败出口（恢复链耗尽 / 登录失效 / 自动选书失败）统一到同一流程：先持久化对应终态，持久化成功后才发送对应通知（失败即返回、不发通知）。
- daemon 循环：移除"未形成终态则窗口内重排"分支（Task 失败 → 记日志 → 排次日）；`ErrTaskRunning` 跳过 + 最短间隔重试守卫保留（ticket 11 / ADR-0008）。
- `NextStart` 决策："now 已在窗口内且无终态"从 `[now, 窗口结束]` 随机改为立即（返回 ≈ now）；"窗口未开始"仍完整窗口随机；终态门控、窗口已过排次日、不补跑、`start==end` 固定时刻不变。
- Task 日期：在 Run 起点取一次 `Clock.Now()` 的 TZ 日期；success 终态与通知、恢复链耗尽 / 登录失效 / 自动选书失败 / 统一收敛各出口的 Date 字段（含 `Result.Date` 摘要与通知日期）全部改用该日期。
- 手动 `run`：与自动 Task 使用相同 Options（删除零值截止时刻的语义分叉）。
- spec / CONTEXT 同步：用户故事 #14/#17 与决策 #8 改为"窗口内立即执行"；决策 #9 补"终态成功落盘才发通知 + Task 日期 = 开始日"；决策 #12 补"run 与自动 Task 相同 finalization"；CONTEXT.md Task 词条补日期归属与不重排说明。

## Acceptance criteria

- [ ] 常驻 daemon 每日仍从完整 Run Window 内随机一次（既有随机调度测试回归）
- [ ] 异常启动/重启在窗口内且无终态 → 立即执行（注入 clock 断言 Task 在启动后立即执行，而非窗口内随机点）
- [ ] 窗口已过后启动 → 当天不自动跑（回归）
- [ ] 无 whole-Task 重排：任何一次暂时性失败（renewal / Reader Context / enter / timed 预算耗尽）都以 failed 终态结束，daemon 不再于窗口内重排第二个完整 Task
- [ ] 手动 `run` 的暂时性失败与自动 Task 相同：failed 终态 + 失败通知（CLI seam 断言）
- [ ] timed report 单次传输失败跳过、会话继续（回归）；连续失败达预算 → failed 终态 + 通知
- [ ] 全部终态与通知日期 = Task 开始日：跨午夜 success（23:50 开始、次日 00:40 完成 → 归属开始日）；跨午夜 failed 覆盖统一收敛出口与至少一个既有失败出口，证明统一 `taskDate` invariant（不要求每个失败出口机械复制完整测试）
- [ ] 终态成功落盘后才发最终通知：任一出口 Save 失败 → 不发通知、Task 返回错误；不存在"已发通知无终态"可达状态（= #15 验收并入）
- [ ] failed 终态下 `weread-cron run` 重试成功更新为 success（回归）
- [ ] 崩溃无终态：重启在窗口内 → 立即开始全新 Task（无 checkpoint）；窗口已过 → 当天不跑
- [ ] spec 用户故事 #14/#17、决策 #8/#9/#12 与 CONTEXT.md 文案已同步
