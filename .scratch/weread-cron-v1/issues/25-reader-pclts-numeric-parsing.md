# 25: Parse numeric `reader.pclts` in Reader state

## Agent Brief

**Category:** bug
**Summary:** Parse numeric JSON values for `reader.pclts` in Reader `__INITIAL_STATE__` to prevent Reader Context extraction failures on real Reader pages.

**Current behavior:**
The Reader state parser (`ParseInitialState`) defines `reader.pclts` as a Go string. When a real WeRead Reader page contains `"pclts":0` as a JSON number, JSON decoding fails with:
`json: cannot unmarshal number into Go struct field InitialState.reader.pclts of type string`.
This error aborts Reader Context extraction and causes both automatic and explicit-book Tasks to fail before starting a Reading Session.

**Desired behavior:**
The Reader state parser accepts both JSON string and JSON numeric representations for `reader.pclts`.
1. When `reader.pclts` is a JSON number (for example `0`), it is parsed and normalized into a string value (for example `"0"`) without JSON unmarshaling error.
2. When `reader.pclts` is a JSON string (for example `"aab32e207a65a466g010615"` or `"0"`), it continues to be preserved as a string.
3. When `reader.pclts` is absent or JSON `null`, it is treated as empty string `""`.
4. Downstream `protocol.go` logic continues to treat `""` and `"0"` as the condition to fall back to `EncodeID(strconv.FormatInt(now.Unix(), 10))` for `pc`.
5. Non-zero numeric values, if encountered, are converted to their decimal string representation.

**Key interfaces:**
- `InitialState.Reader.Pclts`: Change type or custom unmarshaling logic in the Reader state struct so that it accepts both JSON strings and JSON numbers (for example via a dedicated flexible string type or custom `UnmarshalJSON`).
- `ParseInitialState(html string) (*InitialState, error)`: Successfully parses Reader page HTML containing `window.__INITIAL_STATE__` with numeric `pclts`.
- `ReaderContext.Pclts`: Retains string representation in `ReaderContext` so that `EnterReportPayload` and `TimedReportPayload` work without contract changes.

**Acceptance criteria:**
- [x] `ParseInitialState` successfully parses a Reader page where `reader.pclts` is numeric `0`, producing `ReaderContext().Pclts == "0"`.
- [x] `ParseInitialState` successfully parses a Reader page where `reader.pclts` is an encoded string (e.g. `"aab32e207a65a466g010615"`), producing `ReaderContext().Pclts == "aab32e207a65a466g010615"`.
- [x] `ParseInitialState` handles absent or null `reader.pclts`, producing `ReaderContext().Pclts == ""`.
- [x] When `reader.pclts` is numeric `0` or string `"0"`, payload generation (`EnterReportPayload` / `TimedReportPayload`) produces fallback `pc = EncodeID(now)` per existing protocol rules.
- [x] Unit tests cover numeric `0`, string `"0"`, encoded string, and absent `pclts` scenarios.
- [x] All existing test suites continue to pass (`go test ./...`).

**Out of scope:**
- Modifying existing `pc` payload fallback behavior in `protocol.go`.
- Generalizing mixed-type unmarshaling to other Reader state fields without real-world evidence.
- Resolving other items in `docs/protocol-validation-checklist.md` or closing ticket 23.

## Answer

1. **Implementation**:
   - Introduced `flexString` in `internal/weread/readerstate.go` to unmarshal both JSON strings and JSON numbers (`json.Number`) into normalized Go strings, treating null and missing fields as empty string `""`.
   - Updated `InitialState.Reader.Pclts` to `flexString`, while preserving `ReaderContext().Pclts` as standard string.
   - Preserved all downstream `protocol.go` fallback logic without changes: `"0"` and `""` continue to fall back to `EncodeID(now)` in `EnterReportPayload` and `TimedReportPayload`.
2. **Testing**:
   - Added table-driven test `TestParseInitialStatePcltsFlexibility` in `internal/weread/readerstate_test.go` covering numeric `0`, non-zero numeric timestamps, string `"0"`, encoded strings, `null`, missing fields, invalid JSON types (boolean, array), and asserting correct `pc` fallback for both `EnterReportPayload` and `TimedReportPayload`.
   - Added integration test `TestProviderAcceptsNumericPclts` in `internal/readercontext/readercontext_test.go` confirming that `Provider.Fetch` succeeds with real-world style numeric `pclts: 0` without error.
   - Ran `go test ./...` and `go vet ./...` (all passing).
3. **Review**:
   - Ran `/code-review` parallel subagents for Standards and Spec.
   - Refined `flexString` by removing unused presence tracking to avoid Speculative Generality.
   - Expanded unit tests to assert both `EnterReportPayload` and `TimedReportPayload` fallback.
