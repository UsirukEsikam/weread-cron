# 30: fallback `pc` 应在 Reading Session 内保持稳定

**Status:** ready-for-agent

## Agent Brief

**Category:** bug
**Summary:** Reader Context 无可用的 `pclts`（为空或 `"0"`）时，fallback `pc` 必须在 Reading Session 建立时生成一次并被该会话的 enter 与全部 timed reports 复用；当前实现每笔 payload 用报告构造时刻重新生成 `pc`，与官方客户端行为不一致，实证关联长会话拒收。

**Current behavior:**
- 当 `ReaderContext.Pclts` 为空或 `"0"`（真实 Reader 页可返回数字 `0`，ticket 25 已修复解析）时，payload 构造层在每次构造上报 payload 时用 `pc = EncodeID(报告构造时刻的秒级时间戳)` 计算 fallback `pc`。
- enter report 与 timed report 走同一构造层，且每次上报都重新计算，因此一个 Reading Session 内每笔上报携带不同的 fallback `pc`。
- 受控真实账号验证记录（checklist 2026-09-06 会话）：
  - 官方 Web Reader 对一个初始 `pclts` 为数字 `0` 的 Reader 页发送非零 `pc`，并在 enter、连续 timed reports 与真实翻页间复用同一 `pc`/`ps`；`ct`/`rt`/`rn`/`sg`/`s` 与阅读位置字段正常变化；
  - 不带固定 `pc` 的手工长 Task 在约 5–5.5 分钟时被服务端以空对象响应拒收（三种书况、重建容器后均复现）；
  - 临时把 fallback `pc` 固定为该 Reading Session 生命周期后，timed reports 越过原失败点并继续约 7 分钟（至约 7.5 分钟出现 `-2012` 登录超时，属另一问题，见 Out of scope）。
- 影响：长报告会话期间每次上报更换 fallback `pc` 与官方客户端行为不一致，实证关联长会话拒收；会话内 `pc` 稳定使上报在更长时间内被接受。

**Desired behavior:**
- 当 Reader Context 提供可用 `pclts`（非空、非 `"0"`）时：`pc` 继续来自 Reader Context，行为与现状完全一致，本票不改动。
- 当 `pclts` 为空或 `"0"` 时：
  - fallback `pc` 在明确建立新的 Reading Session 时生成一次（值 = `EncodeID(会话建立时刻的秒级时间戳)`，与官方客户端"非零 `pc`、会话内稳定"口径一致）；
  - 该 Reading Session 的 enter report 与全部 timed reports 复用同一个 fallback `pc`，无论各报告的构造时刻如何；
  - 同一 Reading Session 内的 Reader Context 刷新（TTL 到期主动抓取刷新，或恢复链内 refresh Reader Context，均无 re-enter）不改变所复用的 `pc`；
  - 明确建立新的 Reading Session（重新 enter，如异常间隔重建）时生成新的 fallback `pc`，不复用前一会话的值。
- Reading Session 身份按 CONTEXT.md 定义：单本书从 enter report 到结束的连续上报周期；re-enter 即新会话。
- 本票不决定 TTL 刷新或 `-2012` recovery 是否应该 re-enter（维持现状，相关验证由 checklist / ticket 23 跟踪）。

**Key interfaces:**
- `weread.ReaderContext.Pclts`：数据类型与解析不动，`""` 与 `"0"` 仍为"无可用的 pclts"判别条件（ticket 25 语义保留）。
- payload 构造层（`EnterReportPayload` / `TimedReportPayload`，当前签名接收 `rc` 与报告时刻并内部回退 `EncodeID(now)`）：fallback 决策应从"每笔构造时刻"改为"会话建立时刻"。实现方式由实施代理自行选择（例如：把会话已确定的 `pc` 显式传入构造层——可用 `pclts` 时传原值、fallback 时传会话值；或由调用方在会话建立时解析一次并在会话内携带），以行为验收为准，不预先锁定签名形态。
- Reading Session 边界所在地（Task orchestrator 的 enter 建立点与异常间隔重建点）：fallback `pc` 的生成/复用/重置绑定该边界；单纯 Reader Context 刷新路径不得触发重置。

**Acceptance criteria:**
- [ ] `pclts` 可用（非空、非 `"0"`）：`pc` 仍来自 Reader Context，行为与现状完全一致（ticket 25 的解析兼容测试继续通过）。
- [ ] `pclts` 为空或 `"0"`：fallback `pc` 在 Reading Session 建立时生成一次，值 = `EncodeID(会话建立时刻的秒级时间戳)`；同一会话的 enter 与全部 timed reports 携带同一个 `pc`（断言各报告构造时刻不同，如递增的 fake clock）。
- [ ] 同一 Reading Session 内 TTL 主动刷新 Reader Context（无 re-enter）后，后续 timed reports 仍使用同一 fallback `pc`。
- [ ] 恢复链内 refresh Reader Context（无 re-enter）后，继续使用同一 fallback `pc`。
- [ ] 异常间隔重建（重新 enter）后，新会话使用新的 fallback `pc`，不复用前一会话的值。
- [ ] 回归锚点：`TestRunAbnormalIntervalRebuildsSession`（ticket 06）、TTL 主动刷新断言、ticket 25 的 `pclts` 兼容与 fallback 断言在新适配后保持原断言语义并通过。
- [ ] 除 `pc` fallback 生命周期外无其它协议行为变化；`-2012` recovery、TTL 时机、`rt` 语义（ADR-0004）与内部默认数值不变。
- [ ] `go test -count=1 -race ./...` 全部通过。

**Out of scope:**

- `rt` 语义与异常间隔阈值（ADR-0004），以及内部节奏/阈值/预算默认数值。
