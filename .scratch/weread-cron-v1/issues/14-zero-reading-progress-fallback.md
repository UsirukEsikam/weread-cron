# 14: Reading Progress 区分"字段缺失"与"显式零值"

**Finding:** F4 · .scratch/weread-cron-v1/findings/01-implementation-review.md
**Category:** bug
**Blocked by:** None
**Status:** ready-for-agent

**What to build:** Reading Progress 构造区分"字段缺失"与"显式零值"，合法显式零值不被错误回退。

## Current behavior

解析后的 Reading Progress 用数值 0 判定 currentChapter 的 chapterIdx / chapterOffset 是否"不可用"；命中 0 时回退到 progress.book。解析器不记录字段是否存在。显式零值（第 0 章、章节开头）与"缺失"无法区分，合法显式零值会被另一个 progress 对象的回退值覆盖。

## Desired behavior

解析层分别记录"字段缺失"与"显式零值"：currentChapter 存在且显式为零时采用该值，不因零值回退；字段确实缺失时才回退 progress.book。chapterUid 缺失（两个来源都无）仍是"无法构造合法上报"的判定（保持现有错误语义）。

## Key interfaces

- __INITIAL_STATE__ 解析层（Reader 页面解析的 ReadingProgress 构造）：数值解析类型需携带"字段存在性"，或将"缺失"以指针/可选形态表达。
- 现有优先级语义保持：currentChapter 优先、progress.book 回退。
- chapterUid=0 仍视为无位置（现有错误判定不变，除非确认章节 UID 可为 0）。

## Acceptance criteria

- [ ] currentChapter 显式 chapterIdx=0 / chapterOffset=0（且与 progress.book 不同）时采用 currentChapter 值
- [ ] currentChapter 缺失时仍回退 progress.book（回归）
- [ ] 非零优先的现有用例保持通过
- [ ] 章节 UID 缺失的错误判定保持
- [ ] 数字与字符串两种 JSON 形式的零值均可正确解析

## Out of scope

- 改变优先级规则（currentChapter 优先 / progress.book 回退）
- 上报 payload 语义

## 验证记录

Review 输入 F4 已对当前代码确认：

- 解析层数值类型仅存数值、无存在性标志；ReadingProgress 以 `== 0` 判定缺失并回退（chapterIdx / chapterOffset / chapterUid 同理）。
- 现有测试覆盖非零优先、currentChapter 缺失回退、数字/字符串形式，未覆盖"currentChapter 显式零值且与回退值不同"的用例。
