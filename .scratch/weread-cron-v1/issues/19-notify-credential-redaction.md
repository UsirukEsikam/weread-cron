# 19: 通知传输错误不暴露 Bark / 企业微信凭据到日志

**Finding:** F9 · .scratch/weread-cron-v1/findings/01-implementation-review.md
**Category:** bug（安全）
**Blocked by:** None
**Status:** ready-for-agent

**What to build:** 通知的传输层错误记录到日志时不暴露 Bark key / 企业微信 robot key。

## Current behavior

Bark key 位于请求 URL 路径、企业微信 robot key 位于 URL query。Go 的传输层错误（DNS / TLS / 连接失败等）返回的错误串包含完整请求 URL；这些错误被包装后在容器日志中记录，从而泄露通知凭据。普通 HTTP 状态错误（非 2xx）的返回不包含 URL，不受影响。

## Desired behavior

通知传输错误记录到日志时不暴露凭据：对含 URL 的错误做脱敏（剥离或打码 path/query 中的凭据段，或仅保留主机），或让通知层返回不含完整 URL 的错误。日志中不出现 Bark key / 企业微信 robot key。HTTP 状态错误的现有行为保持。

## Key interfaces

- 通知发送层（Bark / 企业微信渠道 + 公共 POST 路径）：统一对传输错误的脱敏/精简处理。
- 返回给调用方（Task 编排层）的错误与写日志的错误使用同一脱敏形态，避免在日志与告警链路中重新泄露。
- 通知失败不影响 Task 结果与终态的语义保持（用户故事 #38）。

## Acceptance criteria

- [ ] 模拟 DNS / TLS / 连接失败时，日志不包含 Bark key
- [ ] 模拟 DNS / TLS / 连接失败时，日志不包含企业微信 robot key
- [ ] 通知层返回/记录的错误不含完整凭据 URL（脱敏或省略）
- [ ] HTTP 状态错误行为不回归
- [ ] 通知失败不影响 Task 结果（回归）

## Out of scope

- 其它日志中可能出现的敏感信息（如 Cookie）——如确认存在，另立 ticket
- 通知渠道配置方式

- Bark URL 形态为 `https://api.day.app/<key>`（key 在路径）；企业微信 webhook URL 的 key 在 query。
- 通知 POST 用底层 HTTP client 发送；传输错误（DNS / TLS / 连接）的 Go 错误串含完整请求 URL，被包装后经 Task 编排层 Warn 日志记录。HTTP 非 2xx 分支返回的"HTTP %d"错误不含 URL。
