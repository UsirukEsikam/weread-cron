# Manual `run` Should Be an Explicit User-Requested Task

## Context

The current `weread-cron run` command uses the same daily terminal-state gate as the daemon scheduler.

If the current day already has a successful automatic or manual Task, another explicit `weread-cron run` invocation is skipped.

The command also uses the configured random Target Duration and normal book-selection configuration rather than requiring the caller to describe the manual Task.

## Finding

An explicit `weread-cron run` invocation represents a direct user request to start a Task now.

Daily automatic scheduling state should not prevent that request.

Manual execution should therefore be independent from the daemon's "already completed today" scheduling gate.

A manual Task should:

- start immediately;
- require an explicit Target Duration from the command line;
- optionally accept a specific bookId;
- use the existing book-selection behavior when no bookId is specified;
- be rejected only when another Task currently holds the deployment task lock.

The Run Window does not constrain manual execution.

Existing daily Terminal State still controls automatic daemon scheduling.

## Terminal State

Manual execution participates in the same persisted daily result state, but an existing successful state must not be downgraded by a later failed manual Task.

Therefore:

- manual success records or preserves `success`;
- manual failure records `failed` only when the current day does not already have `success`;
- if the day already has `success`, a later manual failure leaves the persisted daily state as `success`.

The manual Task itself should still report its own success or failure to the caller and through configured notifications.

## CLI behavior

Expected interface:

    weread-cron run --minutes <N> [--book <bookId>]

`--minutes` is required for manual execution.

`--book` is optional.

When `--book` is omitted, the existing selection rules remain unchanged:

- configured candidate book IDs -> choose using the existing behavior;
- otherwise -> use automatic Shelf selection.

The command-line duration overrides the configured random Target Duration for this Task only.

## Scope boundary

This finding concerns only explicit manual `run` behavior.

It does not change:

- daemon Run Window scheduling;
- automatic daily Task frequency;
- Reader Context or reading-report behavior;
- automatic book-selection rules;
- task-lock semantics;
- protocol-validation behavior.
